The problemمسئله

Run any command with an idle watchdog. When it hangs, whystuck tells you why and what to run instead.هر دستوری را با ناظر بی‌حرکتی اجرا کنید؛ اگر گیر کرد، whystuck دلیلش را می‌گوید و دستور جایگزین را نشان می‌دهد.

The problemمسئله

Humans and AI coding agents lose minutes, or whole sessions, to commands that wait silently: git log in a pager, git commit in an editor, a y/N prompt, a sudo password, a test runner in watch mode. A plain timeout just kills the command and says nothing.انسان‌ها و ایجنت‌های کدنویسی هوش مصنوعی دقیقه‌ها و گاهی یک نشست کامل را به دستورهایی می‌بازند که بی‌صدا منتظر می‌مانند: git log در pager، git commit در ویرایشگر، پرسش y/N، رمز sudo یا ابزار تست در حالت watch. timeout ساده فقط دستور را می‌کُشد و چیزی نمی‌گوید.

What it doesچه می‌کند

Runs the command on a pseudo-terminal with an idle watchdog. When it goes quiet, whystuck inspects the live process (output tail, process tree, /proc, sockets, locks) and says whether it is stuck in a pager, an editor, a y/N or password prompt, watch mode, a lock or an unanswered network connect (13 verdicts), with the evidence and the non-interactive command to run instead. --json and exit code 125 make it usable by agents.دستور را روی یک شبه‌ترمینال با ناظر بی‌حرکتی اجرا می‌کند. وقتی ساکت شد، فرایند زنده را بررسی می‌کند (انتهای خروجی، درخت فرایند، /proc، سوکت‌ها و قفل‌ها) و می‌گوید در pager، ویرایشگر، پرسش y/N یا رمز، حالت watch، قفل یا اتصال شبکهٔ بی‌پاسخ گیر کرده (۱۳ حکم)، همراه با شواهد و دستور غیرتعاملی جایگزین. خروجی --json و کد خروج ۱۲۵ آن را برای ایجنت‌ها قابل‌استفاده می‌کند.

  • 13۱۳verdicts, from pager and editor to lock and networkحکم، از pager و ویرایشگر تا قفل و شبکه
  • 0۰dependencies (one Python file)وابستگی (یک فایل پایتون)
  • 136۱۳۶tests, including real PTY runsآزمون، شامل اجرای واقعی روی PTY

Featuresامکانات

What it does, precisely.دقیقاً چه می‌کند.

01

Real evidence, not guessesشواهد واقعی، نه حدس

Reads the process tree, /proc (stat, wchan, syscall, fds, sockets) and the tail of the output. A blocking read() on a terminal is the strongest "waiting for input" signal; confidence rises with the number of independent signals.درخت فرایند، /proc (‏stat، wchan، syscall، fd و سوکت‌ها) و انتهای خروجی را می‌خواند. read() مسدودشده روی ترمینال قوی‌ترین نشانهٔ «منتظر ورودی» است و اطمینان با تعداد نشانه‌های مستقل بالا می‌رود.

02

13 ordered verdicts۱۳ حکم مرتب

editor, pager, secret, confirm, watch, follow, lock, network, server, stdin_wait, sleeping, busy and unknown. A server, a sleep and a busy process are reported as not stuck and are never killed. If nothing matches the verdict is "unknown" with the raw evidence; it never guesses.editor، pager، secret، confirm، watch، follow، lock، network، server، stdin_wait، sleeping، busy و unknown. سرور، sleep و فرایند پرکار «گیرنکرده» گزارش می‌شوند و هرگز کشته نمی‌شوند. اگر چیزی جور نشود حکم «unknown» با شواهد خام است؛ هرگز حدس نمی‌زند.

03

The non-interactive fixراه‌حل غیرتعاملی

Every verdict prints commands to run instead: git --no-pager log, GIT_EDITOR=true git commit, DEBIAN_FRONTEND=noninteractive apt-get install -y, vitest run, sudo -n, flock -w, connect timeouts.هر حکم دستورهای جایگزین را چاپ می‌کند: ‏git --no-pager log، ‏GIT_EDITOR=true git commit، ‏DEBIAN_FRONTEND=noninteractive apt-get install -y، ‏vitest run، ‏sudo -n، ‏flock -w و مهلت اتصال.

04

Built for agentsساخته‌شده برای ایجنت‌ها

--json prints one document; exit code 125 means stuck and 124 means timeout, anything else is the command's own status. --kill stops the process group only when the verdict is "stuck". A ready AGENTS.md snippet is included.‎--json‎ یک سند JSON چاپ می‌کند؛ کد خروج ۱۲۵ یعنی گیرکرده و ۱۲۴ یعنی مهلت تمام شد، هر کد دیگر وضعیت خود دستور است. ‎--kill‎ فقط وقتی حکم «stuck» است گروه فرایند را متوقف می‌کند. قطعهٔ آمادهٔ AGENTS.md هم همراه آن است.

05

Zero dependencies, read-onlyبدون وابستگی، فقط‌خواندنی

One Python file (3.9+), no network, no telemetry. whystuck --explain PID diagnoses a process that is already hung without touching it.یک فایل پایتون (۳٫۹ به بالا)، بدون شبکه و بدون ردیابی. ‎whystuck --explain PID‎ فرایندی را که از قبل گیر کرده بدون دست‌زدن به آن تشخیص می‌دهد.

06

Offline demo you can trustنمایش آفلاینِ قابل اعتماد

whystuck --demo runs 8 scenarios that stall on purpose (pager, editor, y/N, password, watch, server, lock, network). The programs are stand-ins; the inspection that follows is real. 136 tests, including a check that removing any rule breaks a case.‎whystuck --demo‎ هشت سناریو را اجرا می‌کند که عمداً گیر می‌کنند (pager، ویرایشگر، y/N، رمز، watch، سرور، قفل و شبکه). برنامه‌ها نمونهٔ جایگزین‌اند ولی بازرسیِ بعدی واقعی است. ۱۳۶ آزمون، از جمله بررسی اینکه حذف هر قاعده دست‌کم یک مورد را خراب می‌کند.

  3. Run a command under watchاجرای دستور زیر نظر

How it worksچطور کار می‌کند

Four steps, no magic.چهار گام، بدون جادو.

Run on a PTYاجرا روی PTY

The command runs inside a pseudo-terminal, so colours, pagers and prompts all appear. whystuck tracks the time of the last output byte (or forwarded keystroke) and a rolling tail of the output.دستور داخل یک شبه‌ترمینال اجرا می‌شود، پس رنگ‌ها، pagerها و پرسش‌ها همه ظاهر می‌شوند. whystuck زمان آخرین بایت خروجی (یا کلیدِ ارسال‌شده) و انتهای خروجی را دنبال می‌کند.

One snapshot when it goes quietیک عکس لحظه‌ای وقتی ساکت شد

After --idle seconds it snapshots the process tree: stat, cmdline, wchan, /proc/PID/syscall, open fds, TCP sockets (LISTEN and SYN_SENT), a 0.5 s CPU sample and lock holders.پس از ‎--idle‎ ثانیه از درخت فرایند عکس می‌گیرد: ‏stat، ‏cmdline، ‏wchan، ‏/proc/PID/syscall، fdهای باز، سوکت‌های TCP (‏LISTEN و SYN_SENT)، نمونهٔ ۰٫۵ثانیه‌ای CPU و نگه‌دارندگان قفل.

An ordered rule tableجدول قاعدهٔ مرتب

classify() walks 13 rules; the first with evidence wins and the others are listed as "also matched". Confidence comes from how many independent signals agree. If nothing matches the verdict is unknown; it never guesses.‏classify()‎ از ۱۳ قاعده می‌گذرد؛ اولین قاعده‌ای که شاهد دارد برنده است و بقیه «هم‌خوان‌شده» فهرست می‌شوند. اطمینان از تعداد نشانه‌های مستقلِ هم‌نظر می‌آید. اگر چیزی جور نشود حکم unknown است؛ هرگز حدس نمی‌زند.

Verdict, fix, exit codeحکم، راه‌حل، کد خروج

It prints the verdict, the evidence and the non-interactive fix on stderr, keeps stdout for the command, and exits 125 when it stopped a stuck command (--kill) or 124 on timeout.حکم، شواهد و راه‌حل غیرتعاملی را روی stderr چاپ می‌کند، stdout را برای خود دستور نگه می‌دارد و وقتی دستورِ گیرکرده را متوقف کرده (‎--kill‎) با ۱۲۵ و در مهلت تمام‌شده با ۱۲۴ خارج می‌شود.

Honest limitsمحدودیت‌های صادقانه

What it does not do. Please read.چه کارهایی نمی‌کند. لطفاً بخوانید.

  • Only silence is detected. A program that prints a spinner or heartbeat forever is not idle, so it is not diagnosed.فقط سکوت تشخیص داده می‌شود. برنامه‌ای که همیشه اسپینر یا ضربان چاپ می‌کند بی‌حرکت نیست و تشخیص داده نمی‌شود.
  • Prompt detection looks at the last line of output. Free-form questions end up as stdin_wait or unknown; editors and pagers are recognised by process name.تشخیص پرسش به آخرین خط خروجی نگاه می‌کند. پرسش‌های آزاد به stdin_wait یا unknown می‌رسند؛ ویرایشگرها و pagerها از روی نام فرایند شناخته می‌شوند.
  • Network: only a TCP connect in progress (SYN_SENT) is detected. DNS stalls and established-but-silent connections are not diagnosed.شبکه: فقط اتصال TCPِ در حال برقراری (SYN_SENT) تشخیص داده می‌شود. توقف DNS و اتصال برقرار ولی ساکت تشخیص داده نمی‌شود.
  • "busy" means at least 25% of a core in a 0.5 s sample: an infinite loop looks exactly like a long computation. "server" cannot tell a healthy server from one that is hung inside.«busy» یعنی دست‌کم ۲۵٪ یک هسته در نمونهٔ ۰٫۵ثانیه‌ای: حلقهٔ بی‌پایان دقیقاً مثل محاسبهٔ طولانی دیده می‌شود. «server» سرور سالم را از سرورِ گیرکرده در درون تشخیص نمی‌دهد.
  • Linux has full evidence. macOS is best effort and was not tested on a real Mac in v0.1. Windows is not supported (use WSL).لینوکس شواهد کامل دارد. مک در حد تلاش است و در v0.1 روی مک واقعی آزموده نشده. ویندوز پشتیبانی نمی‌شود (از WSL استفاده کنید).
  • --json includes the last 4000 characters of output: if your command prints secrets, they are in there. Suggested fixes come from a small table of well-known tools; check them before running anything destructive.‎--json‎ ۴۰۰۰ نویسهٔ آخر خروجی را دارد: اگر دستور شما رمز چاپ کند آنجاست. راه‌حل‌های پیشنهادی از جدول کوچکی از ابزارهای شناخته‌شده می‌آیند؛ پیش از اجرای هر کار مخرب بررسی‌شان کنید.

FAQپرسش‌های متداول

Questions people ask.پرسش‌هایی که می‌پرسند.

Does whystuck kill my command?آیا whystuck دستور من را می‌کُشد؟

Only with --kill, and only when the verdict says stuck. Servers, sleeping and busy processes are never killed. Without --kill it only reports and the command keeps running.فقط با ‎--kill‎ و فقط وقتی حکم «گیرکرده» باشد. سرور، sleep و فرایند پرکار هرگز کشته نمی‌شوند. بدون ‎--kill‎ فقط گزارش می‌دهد و دستور ادامه می‌دهد.

How do I use it from an AI agent?از یک ایجنت هوش مصنوعی چطور استفاده کنم؟

It is a plain CLI, so it is agent-agnostic: run whystuck --json --kill --idle 20 -- COMMAND and branch on the exit code (125 means stuck: read verdicts[0].fixes and re-run non-interactively). Paste docs/AGENTS.snippet.md into your AGENTS.md or CLAUDE.md.یک CLI ساده است، پس به ایجنت خاصی وابسته نیست: ‎whystuck --json --kill --idle 20 -- COMMAND‎ را اجرا کنید و روی کد خروج تصمیم بگیرید (۱۲۵ یعنی گیرکرده: ‏verdicts[0].fixes را بخوانید و غیرتعاملی دوباره اجرا کنید). فایل docs/AGENTS.snippet.md را در AGENTS.md یا CLAUDE.md بگذارید.

Is it on PyPI?آیا در PyPI هست؟

Not yet. Install from GitHub with pip install git+https://github.com/mrzroot/whystuck, or copy the single file whystuck.py anywhere on your PATH.هنوز نه. از گیت‌هاب با ‎pip install git+https://github.com/mrzroot/whystuck‎ نصب کنید یا فایل تکیِ whystuck.py را در PATH بگذارید.
