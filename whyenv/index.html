You changed the variable and nothing changed? whyenv shows which source wins and which edit is ignored.متغیر را عوض کردید و چیزی عوض نشد؟ whyenv نشان می‌دهد کدام منبع برنده است و کدام ویرایش نادیده گرفته می‌شود.

The problemمسئله

You edited .env.local, restarted, and the app still calls the old server. A variable exported once in ~/.bashrc, or in Windows Environment Variables, silently beats .env.local in Vite, Next.js, CRA and dotenv; VITE_ and NEXT_PUBLIC_ values are frozen into the build; a container keeps the environment it was created with; environment: beats env_file:. People and AI agents answer "restart the server" and edit the same file again.ویرایش .env.local را کردید، سرور را دوباره راه انداختید و برنامه هنوز سرور قدیمی را صدا می‌زند. متغیری که یک بار در ~/.bashrc یا در Environment Variables ویندوز export شده در Vite، Next.js، CRA و dotenv بی‌صدا از .env.local جلو می‌افتد؛ مقدارهای VITE_ و NEXT_PUBLIC_ داخل بیلد ثابت می‌شوند؛ کانتینر همان محیطی را نگه می‌دارد که با آن ساخته شده؛ environment: از env_file: قوی‌تر است. آدم‌ها و ایجنت‌ها می‌گویند «سرور را ری‌استارت کن» و همان فایل را دوباره ویرایش می‌کنند.

What it doesچه می‌کند

whyenv NAME lists every place that can define the variable (your shell, .env.local, .env, docker-compose.yml and more) in the order of your framework, marks the one that wins, and says which of your edits is being ignored, including the shell startup file or the Windows registry entry that probably exports the old value. It also flags traps around the value: a missing client prefix, a build older than the .env file, an empty value that wins, BOM, CRLF, a container that was not recreated. Names that look secret are shown as hidden. It only reads files; it never runs your project.دستور whyenv NAME همهٔ جاهایی را که می‌توانند متغیر را تعریف کنند (شل شما، .env.local، .env، docker-compose.yml و…) به ترتیب فریم‌ورک شما فهرست می‌کند، برنده را علامت می‌زند و می‌گوید کدام ویرایش شما نادیده گرفته می‌شود، از جمله فایل راه‌اندازی شل یا ورودی رجیستری ویندوز که احتمالاً مقدار قدیمی را export می‌کند. تله‌های اطراف مقدار را هم نشان می‌دهد: پیشوند کلاینت جاافتاده، بیلد قدیمی‌تر از فایل .env، مقدار خالیِ برنده، BOM، CRLF، کانتینری که دوباره ساخته نشده. نام‌های شبیه رمز پنهان نشان داده می‌شوند. فقط فایل می‌خواند و پروژه را اجرا نمی‌کند.

Featuresامکانات

What it does, precisely.دقیقاً چه می‌کند.

01

Precedence per frameworkاولویت برای هر فریم‌ورک

From each vendor's documentation: Vite (process > .env.[mode].local > .env.[mode] > .env.local > .env), Next.js and CRA, plain dotenv (process wins unless override) and Docker Compose (environment: beats env_file:).از مستندات هر فروشنده: Vite (‏process > .env.[mode].local > .env.[mode] > .env.local > .env)، Next.js و CRA، dotenv ساده (پروسه برنده است مگر override) و Docker Compose (‏environment: از env_file: قوی‌تر است).

02

The edit that is ignoredویرایشی که نادیده گرفته می‌شود

SHADOWED is a confirmed case: your edit to .env.local is ignored because the shell already exports the variable, with the exact unset command for bash, PowerShell or cmd.SHADOWED یعنی مورد تأییدشده: ویرایش شما در .env.local نادیده گرفته می‌شود چون شل از قبل متغیر را export کرده، با دستور دقیق unset برای bash، PowerShell یا cmd.

03

Who exported the old valueچه کسی مقدار قدیمی را export کرده

Best effort: ~/.bashrc, ~/.profile, /etc/profile.d and .envrc in the project and its parents; on Windows the user and machine registry keys. Reported as "probably set at" because whyenv cannot see the process that did it.تا حد ممکن: ‏~/.bashrc، ‏~/.profile، ‏/etc/profile.d و ‏.envrc در پروژه و پوشه‌های بالاتر؛ در ویندوز کلیدهای رجیستری کاربر و ماشین. با عبارت «احتمالاً در اینجا تنظیم شده» گزارش می‌شود چون whyenv فرایندی را که این کار را کرده نمی‌بیند.

04

Traps around the valueتله‌های اطراف مقدار

A missing VITE_ or NEXT_PUBLIC_ prefix, a build directory older than .env, an empty value that wins, a similarly named variable, BOM, CRLF, spaces around =, inline #, duplicate keys, unterminated quotes, a container that was not recreated.پیشوند VITE_ یا NEXT_PUBLIC_ جاافتاده، پوشهٔ بیلد قدیمی‌تر از .env، مقدار خالیِ برنده، متغیری با نام مشابه، BOM، CRLF، فاصله دور =، علامت # وسط خط، کلیدهای تکراری، نقل‌قول بسته‌نشده، کانتینری که دوباره ساخته نشده.

05

Secrets stay hiddenرمزها پنهان می‌مانند

Names containing KEY, SECRET, TOKEN, PASS and similar are shown as hidden with only a length; --show-values is explicit. It reads files and the Windows registry, never sends anything over the network and never writes.نام‌های شامل KEY، SECRET، TOKEN، PASS و مانند آن فقط با طول و به‌صورت پنهان نشان داده می‌شوند؛ ‎--show-values صریح است. فایل‌ها و رجیستری ویندوز را می‌خواند، چیزی را روی شبکه نمی‌فرستد و چیزی نمی‌نویسد.

06

For humans and agentsبرای آدم‌ها و ایجنت‌ها

--json for scripts, exit code 1 on a confirmed shadowed value and 2 when the variable is defined nowhere, and a snippet for AGENTS.md / CLAUDE.md so an assistant runs whyenv instead of editing .env in circles.خروجی --json برای اسکریپت، کد خروج ۱ برای مقدار تأییدشدهٔ shadowed و ۲ وقتی متغیر هیچ‌جا تعریف نشده، و یک snippet برای AGENTS.md / CLAUDE.md تا دستیار به‌جای چرخیدن دور .env از whyenv استفاده کند.

How it worksچطور کار می‌کند

Four steps, no magic.چهار گام، بدون جادو.

Detect the stackتشخیص پشته

Looks at package.json, config files and docker-compose.yml to pick Vite, Next.js, CRA, plain dotenv or Compose; -f and -m force the framework and mode.package.json، فایل‌های پیکربندی و docker-compose.yml را می‌بیند تا Vite، Next.js، CRA، dotenv ساده یا Compose را انتخاب کند؛ ‎-f‎ و ‎-m‎ فریم‌ورک و مود را اجباری می‌کنند.

Apply the real precedenceاعمال اولویت واقعی

Reads your actual .env files, the process environment of the shell it runs in and the Compose file, and orders them the way the framework documentation says: highest first, one winner..envهای واقعی شما، محیط پروسهٔ شلی که در آن اجرا می‌شود و فایل Compose را می‌خواند و به ترتیب مستندات فریم‌ورک می‌چیند: قوی‌ترین اول، یک برنده.

Find who exported itیافتن چه کسی export کرده

If the winner is the shell, it greps ~/.bashrc, ~/.profile, /etc/profile.d and .envrc (and on Windows the registry) and reports the file and line as "probably set at".اگر برنده شل باشد، ‏~/.bashrc، ‏~/.profile، ‏/etc/profile.d و ‏.envrc (و در ویندوز رجیستری) را می‌گردد و فایل و خط را با عبارت «احتمالاً در اینجا تنظیم شده» گزارش می‌کند.

Three levels, one fixسه سطح، یک راه‌حل

SHADOWED (confirmed, exit 1), CHECK (could be the cause), NOTE (a trap nearby). Each says why and gives the command; secrets are hidden unless --show-values.SHADOWED (تأییدشده، کد ۱)، CHECK (می‌تواند علت باشد)، NOTE (تله‌ای نزدیک). هرکدام دلیل و دستور را می‌گوید؛ رمزها پنهان‌اند مگر با ‎--show-values‎.

Honest limitsمحدودیت‌های صادقانه

What it does not do. Please read.چه کارهایی نمی‌کند. لطفاً بخوانید.

  • It sees files and the Windows registry, not other processes. An IDE, docker -e, a CI runner or a parent shell can set a value that whyenv reports only as "exported by hand, by your IDE or by a parent process".فایل‌ها و رجیستری ویندوز را می‌بیند، نه فرایندهای دیگر. IDE، ‏docker -e، اجراکنندهٔ CI یا شل والد می‌توانند مقداری بسازند که whyenv فقط با عبارت «با دست، توسط IDE یا فرایند والد export شده» گزارش می‌کند.
  • It reads the environment of its own process: run it from the same shell you start the dev server from.محیط پروسهٔ خودش را می‌خواند: از همان شلی اجرا کنید که سرور توسعه را از آن راه می‌اندازید.
  • The Compose reader is a minimal YAML subset (services, environment: as map or list, env_file:). Anchors, extends, profiles and ${VAR:-default} inside values are not resolved: verify with docker compose config.خواننده‌ٔ Compose زیرمجموعهٔ کوچکی از YAML است (services، ‏environment: به‌صورت map یا list، ‏env_file:). anchor، ‏extends، ‏profiles و ‎${VAR:-default}‎ داخل مقدارها حل نمی‌شوند: با docker compose config تأیید کنید.
  • Rules follow each framework's documentation as of October 2026 and can go stale. NODE_ENV is not read from your shell (development is assumed unless -m). The Windows registry reader and PowerShell hints are implemented but untested on Windows.قواعد از مستندات هر فریم‌ورک تا اکتبر ۲۰۲۶ پیروی می‌کنند و ممکن است کهنه شوند. NODE_ENV از شل شما خوانده نمی‌شود (مگر با -m، development فرض می‌شود). خواننده‌ٔ رجیستری ویندوز و راهنمای PowerShell پیاده شده‌اند ولی روی ویندوز آزموده نشده‌اند.

Questions people ask.پرسش‌هایی که می‌پرسند.

Will it print my secrets?آیا رمزهای من را چاپ می‌کند؟

No. Names containing KEY, SECRET, TOKEN, PASS and similar are shown as hidden with only a length. --show-values is explicit, and --json follows the same rule.نه. نام‌های شامل KEY، SECRET، TOKEN، PASS و مانند آن فقط با طول و به‌صورت پنهان نشان داده می‌شوند. ‎--show-values‎ صریح است و ‎--json‎ هم همین قاعده را دارد.

Does it run my project or change files?آیا پروژه را اجرا یا فایل‌ها را تغییر می‌دهد؟

No. It reads files (and the Windows registry), never executes your project, never writes and never uses the network.نه. فایل‌ها (و رجیستری ویندوز) را می‌خواند، پروژه را اجرا نمی‌کند، چیزی نمی‌نویسد و از شبکه استفاده نمی‌کند.

Why does it say "probably set at"?چرا می‌گوید «احتمالاً تنظیم شده در»؟

Because it can only see files, not the process that actually exported the variable. A matching line in ~/.bashrc is strong evidence, not proof.چون فقط فایل‌ها را می‌بیند، نه فرایندی که واقعاً متغیر را export کرده. خط مطابق در ~/.bashrc شاهد قوی است، نه اثبات.

How does an AI agent use it?ایجنت هوش مصنوعی چطور از آن استفاده کند؟

Paste docs/AGENTS.snippet.md into AGENTS.md or CLAUDE.md so it runs whyenv instead of editing .env in circles. --json is machine-readable; exit 1 means a confirmed shadowed value, 2 means undefined.فایل docs/AGENTS.snippet.md را در AGENTS.md یا CLAUDE.md بگذارید تا به‌جای چرخیدن دور .env از whyenv استفاده کند. ‎--json‎ ماشین‌خوان است؛ کد ۱ یعنی مقدار shadowed تأییدشده و ۲ یعنی تعریف‌نشده.
