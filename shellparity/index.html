The problemمسئله

AI coding agents run commands in a non-login, non-interactive shell that never reads ~/.zshrc or ~/.bashrc. Everything you configured there is invisible: nvm and pyenv versions, proxies, locale, the SSH agent, API keys, git signing. You get command not found, the wrong Node, hangs behind a proxy, mangled Persian text, and end up diffing env output by hand.ایجنت‌های کدنویسی هوش مصنوعی دستورها را در شلی بدون login و بدون حالت تعاملی اجرا می‌کنند که ~/.zshrc و ~/.bashrc را نمی‌خواند. هرچه آنجا تنظیم کرده‌اید دیده نمی‌شود: نسخهٔ nvm و pyenv، پروکسی، زبان و UTF-8، ssh-agent، کلیدهای API و امضای git. نتیجه command not found، نسخهٔ اشتباه Node، گیرکردن پشت پروکسی و متن فارسی خراب است و آخرش خروجی env را با چشم مقایسه می‌کنید.

What it doesچه می‌کند

Starts your shell twice on the same machine, like a terminal (login and interactive on a pty) and like an agent (bash -c, or login, interactive, bare), takes read-only snapshots and compares them: PATH, 27 common tools and their versions, project requirements (.nvmrc, engines, requires-python), proxy, locale with a real UTF-8 test, SSH agent, git signing, environment names and secret-looking names (never values), TTY and TERM. Each finding names the dotfile and line and prints the exact fix, for example the export lines for ~/.bash_env.شل شما را دو بار روی همان دستگاه راه می‌اندازد: یک بار مثل ترمینال (login و تعاملی روی pty) و یک بار مثل ایجنت (‏bash -c یا login، تعاملی و bare)، از هرکدام عکس فقط‌خواندنی می‌گیرد و مقایسه می‌کند: PATH، ۲۷ ابزار رایج و نسخه‌شان، نیازمندی پروژه (‏.nvmrc، ‏engines، ‏requires-python)، پروکسی، زبان با آزمون واقعی UTF-8، ssh-agent، امضای git، نام متغیرهای محیطی و نام‌های شبیه رمز (هرگز مقدار)، TTY و TERM. هر یافته نام فایل و شمارهٔ خط را می‌گوید و راه‌حل دقیق را چاپ می‌کند، مثلاً خط‌های export برای ~/.bash_env.

Featuresامکانات

What it does, precisely.دقیقاً چه می‌کند.

01

Same machine, two shellsیک دستگاه، دو شل

Probes your shell as a terminal starts it and as an agent runs it (plain -c, login, interactive or bare), each in a fresh child process. A mode matrix shows what each startup mode sees.شل را همان‌طور که ترمینال اجرا می‌کند و همان‌طور که ایجنت اجرا می‌کند (‏-c ساده، login، تعاملی یا bare) می‌سنجد، هرکدام در یک فرایند فرزند تازه. ماتریس حالت‌ها نشان می‌دهد هر حالت چه می‌بیند.

02

It names the file and the lineفایل و خط را نام می‌برد

Findings point at the exact startup line, for example "~/.bashrc:8: export PATH=… (below the interactive-only guard at line 2)", so you see why the agent never loaded it.یافته‌ها به خط دقیق فایل راه‌اندازی اشاره می‌کنند، مثل «‏~/.bashrc:8: export PATH=… (پایین نگهبانِ فقط‌تعاملی در خط ۲)»، تا ببینید چرا ایجنت آن را بارگذاری نکرده.

03

The fix goes in the right fileراه‌حل در فایل درست

~/.zshenv for zsh, the file named by $BASH_ENV for non-interactive bash, ~/.profile for login bash, and the honest answer that plain sh reads nothing. Fixes are printed, never applied.‏~/.zshenv برای zsh، فایلِ معرفی‌شده با ‎$BASH_ENV‎ برای bash غیرتعاملی، ‏~/.profile برای bash با login، و پاسخ صادقانه که sh ساده چیزی نمی‌خواند. راه‌حل‌ها چاپ می‌شوند، هرگز اعمال نمی‌شوند.

04

A real UTF-8 testآزمون واقعی UTF-8

The shell counts the characters of a Persian word (4 characters, 8 bytes). A byte count means the shell is not UTF-8, even when LANG claims otherwise.شل حروف یک کلمهٔ فارسی را می‌شمارد (۴ حرف، ۸ بایت). اگر بایت بشمارد یعنی UTF-8 نیست، حتی اگر LANG ادعای دیگری کند.

05

Safe by designایمن از پایه

Secret values are never read (names only), credentials in proxy URLs are masked, and shellparity never edits your files; --write-snippet writes only the file you name. The tests assert this end to end.مقدار رمزها هرگز خوانده نمی‌شود (فقط نام)، اطلاعات ورود در نشانی پروکسی پوشانده می‌شود و shellparity فایلی را ویرایش نمی‌کند؛ ‎--write-snippet‎ فقط فایلی را که نام ببرید می‌نویسد. آزمون‌ها این را سرتاسر بررسی می‌کنند.

06

Ready for agents and CIآماده برای ایجنت و CI

--json, --markdown for your AGENTS.md or CLAUDE.md, and --fail-on error as a hook. --demo runs against a fake home directory, so none of your dotfiles are read.‎--json‎، ‎--markdown‎ برای AGENTS.md یا CLAUDE.md و ‎--fail-on error‎ به‌عنوان هوک. ‎--demo‎ روی یک پوشهٔ خانگی ساختگی اجرا می‌شود و هیچ‌کدام از dotfileهای شما خوانده نمی‌شود.

How it worksچطور کار می‌کند

Four steps, no magic.چهار گام، بدون جادو.

Probeسنجش

One POSIX sh script is sourced by each shell and writes records to a temp file, so banners and prompts from your rc files cannot corrupt the result. It only reads: command -v, --version, git config, alias, umask and allow-listed variables.یک اسکریپت POSIX sh در هر شل بارگذاری می‌شود و رکوردها را در فایل موقت می‌نویسد، پس بنر و پرسش‌های rc فایل‌ها نتیجه را خراب نمی‌کنند. فقط می‌خواند: ‏command -v، ‏--version، ‏git config، ‏alias، ‏umask و متغیرهای مجاز.

Five startup modesپنج حالت راه‌اندازی

human (-l -i on a pty), plain (-c), login, interactive and bare (env -i). By default each starts from a clean login-like environment, so the question answered is what the startup files provide.‏human (‏-l -i روی pty)، ‏plain (‏-c)، ‏login، ‏interactive و ‏bare (‏env -i). به‌طور پیش‌فرض هرکدام از یک محیط تمیز شبیه login شروع می‌کند، پس پرسشِ پاسخ‌داده‌شده این است که فایل‌های راه‌اندازی چه چیزی فراهم می‌کنند.

Compareمقایسه

compare(human, agent) is a pure function: two snapshots in, ranked findings out. No processes and no files, which is why it is easy to test.‏compare(human, agent)‎ یک تابع خالص است: دو عکس لحظه‌ای می‌گیرد و یافته‌های رتبه‌بندی‌شده می‌دهد. بدون فرایند و بدون فایل، برای همین آزمونش آسان است.

Adviseپیشنهاد

Your rc files are searched textually (export NAME=, PATH entries, version-manager markers, one level of source) so the report can say ~/.zshrc:14, and the fix is written for the right file.rc فایل‌ها متنی جست‌وجو می‌شوند (‏export NAME=، مسیرهای PATH، نشانه‌های مدیر نسخه، یک سطح source) تا گزارش بتواند بگوید ‏~/.zshrc:14، و راه‌حل برای فایل درست نوشته می‌شود.

Honest limitsمحدودیت‌های صادقانه

What it does not do. Please read.چه کارهایی نمی‌کند. لطفاً بخوانید.

  • Linux and macOS, bash, zsh and sh only. No fish, PowerShell or native Windows (use WSL). CI runs on Ubuntu; the macOS job is informational and has not been run on a real Mac.فقط لینوکس و مک، و فقط bash، zsh و sh. بدون fish، PowerShell و ویندوز بومی (از WSL استفاده کنید). CI روی Ubuntu اجرا می‌شود؛ کار macOS اطلاعاتی است و روی مک واقعی اجرا نشده.
  • "The agent shell" is a model. Some agents run bash -c, some a login shell, some snapshot your environment. Pick the closest --agent-mode and read the result as what the startup files provide in that mode, not a trace of one product.«شل ایجنت» یک مدل است. بعضی ایجنت‌ها bash -c اجرا می‌کنند، بعضی شل login و بعضی از محیط شما عکس می‌گیرند. نزدیک‌ترین ‎--agent-mode‎ را انتخاب کنید و نتیجه را «فایل‌های راه‌اندازی در آن حالت چه می‌دهند» بخوانید، نه ردگیری یک محصول.
  • Rc-file lookup is textual. It does not evaluate your dotfiles, so a matching line may sit in a branch that did not run, ZDOTDIR is not followed, and dynamically built definitions are not found.جست‌وجوی rc فایل‌ها متنی است. dotfileها را اجرا نمی‌کند، پس خط مطابق ممکن است در شاخه‌ای باشد که اجرا نشده، ZDOTDIR دنبال نمی‌شود و تعریف‌های پویا پیدا نمی‌شوند.
  • Your interactive rc files do run (that is the point), so a slow nvm makes it slow. Each mode has a timeout and a failed probe is reported as such.rc فایل‌های تعاملی شما اجرا می‌شوند (همین هدف است)، پس nvm کند آن را کند می‌کند. هر حالت مهلت دارد و سنجش شکست‌خورده گزارش می‌شود.
  • Version checks are coarse (major for Node, major.minor for Python). git and ssh checks are configuration-level: it does not run gpg or contact an ssh-agent.بررسی نسخه درشت است (اصلی برای Node، اصلی.فرعی برای Python). بررسی git و ssh در سطح پیکربندی است: gpg اجرا نمی‌کند و با ssh-agent تماس نمی‌گیرد.
  • Suggested fixes are printed, never applied, and are a starting point: pinning an nvm directory freezes that version until you re-pin.راه‌حل‌ها چاپ می‌شوند و هرگز اعمال نمی‌شوند و نقطهٔ شروع‌اند: سنجاق‌کردن پوشهٔ nvm آن نسخه را تا سنجاق بعدی ثابت می‌کند.

FAQپرسش‌های متداول

Questions people ask.پرسش‌هایی که می‌پرسند.

Does shellparity read my secrets?آیا shellparity رمزهای من را می‌خواند؟

No. Secret-looking variables are listed by name only, values are never read or stored, credentials in proxy URLs are masked, and secret-named assignments quoted from rc files are redacted. The tests assert this end to end.نه. متغیرهای شبیه رمز فقط با نام فهرست می‌شوند، مقدارشان هرگز خوانده یا ذخیره نمی‌شود، اطلاعات ورود در نشانی پروکسی پوشانده می‌شود و تخصیص‌های با نام رمز در خط‌های نقل‌شده از rc فایل‌ها سیاه می‌شوند. آزمون‌ها این را سرتاسر بررسی می‌کنند.

Does it change my dotfiles?آیا dotfileهای من را تغییر می‌دهد؟

Never. Fixes are printed. --write-snippet FILE is the only way it writes a file, and only the one you name.هرگز. راه‌حل‌ها چاپ می‌شوند. ‎--write-snippet FILE‎ تنها راهی است که فایل می‌نویسد و فقط همان فایلی که نام ببرید.

Which agent does it model?کدام ایجنت را مدل می‌کند؟

None in particular. Choose --agent-mode plain, login, interactive or bare to match how your agent starts its shell, and use --shell all to check every bash, zsh and sh on the machine.هیچ ایجنت خاصی را. ‎--agent-mode‎ را plain، login، interactive یا bare انتخاب کنید تا با شیوهٔ راه‌اندازی شل در ایجنت شما بخواند و با ‎--shell all‎ همهٔ bash، zsh و shهای دستگاه را بسنجید.
