پرونده: عبارت گم‌شدهٔ تلاش مجدد

پرسش «retry token» را دارد، اما راهنمای مرتبط در دو قطعه برمی‌گردد. پیش از تغییر مدل برداری، مرز قطعه را بررسی کنید.

آزمایش بالا یک ترمیم نمونه را نشان می‌دهد: هم‌پوشانی می‌تواند عبارت کامل را در یک قطعه حفظ کند. این آزمون دقت بازیابی نیست.

limit 20 • overlap 00
… the retry to  |  ken from …

limit 20 • overlap 11
… the retry token from …

شواهد را دنبال کنید، نه حدس را

  1. بازرسی

    فایل‌های محلی را بررسی کنید و ببینید متن معنادار روی مرز قطعه شکسته است یا نه.

  2. جست‌وجوی آزمایشی

    همان پرسش را برای مقایسهٔ BM25 و بازیابی سه‌حرفی به کار ببرید و متن بازیابی‌شده را بخوانید.

  3. ثبت

    پیش از تنظیم، گزارش HTML یا JSON ذخیره کنید و با همان ورودی دوباره بسنجید.

دو روش بازیابی و دو سؤال

روشسؤال مفیدنقطهٔ کور
BM25کدام سند واژه‌های مفید پرسش را دارد؟بیان متفاوت ممکن است جفت نشود.
سه‌حرفیآیا اشتراک حروف شکل املایی دیگری را می‌یابد؟شباهت املایی یعنی معنای یکسان نیست.

با مجموعه‌سند محلی تکرار کنید

git clone https://github.com/mrzroot/ragxray
cd ragxray
python -m pip install .
ragxray inspect docs/ --chunk-size 800 --overlap 100 --html report.html
ragxray probe docs/ --query "authentication retry" --json

مخزن Python 3.9+ را مشخص کرده و وابستگی زمان اجرا ندارد. docs/ را با پوشهٔ اسناد محلی جایگزین کنید.

آیا هم‌پوشانی بیشتر همیشه بهتر است؟

نه. ممکن است زمینه را حفظ کند، اما متن تکراری هم می‌سازد. چند پرسش ثابت را با هر تنظیم بسنجید.

آیا RagXray کیفیت پاسخ تولیدی را می‌سنجد؟

تمرکز آن مرز قطعه و بازیابی واژه‌محور است، نه درستی پاسخ تولیدشده.
